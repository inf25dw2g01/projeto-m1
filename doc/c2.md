# C2 : Resources

## Recursos da API

A API do Gym Tracker expõe três recursos principais, relacionados entre si através de relações 1:N e N:M implementadas via Sequelize.

---

## 2.1 Users (Atletas)

Representa os atletas registados na plataforma. Um utilizador é criado automaticamente no primeiro login via OAuth 2.0 ou Basic Auth através do mecanismo `User.findOrCreate` do Sequelize. No momento do registo, é gerada automaticamente uma **API Key** única associada à conta via `crypto.randomBytes(32).toString('hex')`.

| Campo      | Tipo    |Descrição                                        |
|------------|---------|-------------------------------------------------|
| id         | integer |Identificador único (auto-increment)             |
| firstName  | string  |Primeiro nome                                    |
| lastName   | string  |Apelido                                          |
| email      | string  |Email único — chave de identificação             |
| password   | string  |Hash bcrypt (null para utilizadores OAuth)       |
| apiKey     | string  |Chave stateless gerada com `crypto.randomBytes`  |

**Endpoints de User:**

| Método | Path               | Descrição                                          |
|--------|--------------------|----------------------------------------------------|
| GET    | `/users/me`        |Informação de login geral                           |
| GET    | `/google/me`       |Informação do user ao fazer login com conta Google  |
| GET    | `/github/me`       |Informação do user ao fazer login com conta Github  |
| POST   | `/discord/me`      |Informação do user ao fazer login com conta Discord |

---

## 2.2 Workouts (Planos de Treino)

Representa os planos de treino criados pelos atletas. Cada workout pertence a um único utilizador (**relação 1:N**) e pode conter vários exercícios com séries e repetições personalizadas (**relação N:M** via tabela intermédia `WorkoutExercise`).

Um workout pode ser **público** (visível a todos) ou **privado** (visível apenas ao autor).

| Campo       | Tipo    |Descrição                                  |
|-------------|---------|-------------------------------------------|
| id          | integer |Identificador único                        |
| title       | string  |Nome do plano de treino                    |
| description | string  |Descrição opcional                         |
| visibility  | enum    |`public` ou `private`                      |
| UserId      | integer |FK — dono do treino (relação 1:N)          |
| Exercises   | array   |Exercícios associados (relação N:M)        |

**Endpoints:**

| Método | Path               | Descrição                                        |
|--------|--------------------|--------------------------------------------------|
| GET    | `/workouts/public` | Lista todos os treinos públicos da comunidade    |
| GET    | `/workouts/me`     | Lista os treinos do utilizador autenticado       |
| GET    | `/workouts/{id}`   | Detalhes de um treino (privado: só o dono acede) |
| POST   | `/workouts`        | Cria novo treino com exercícios associados       |
| PUT    | `/workouts/{id}`   | Atualiza treino — apenas o autor pode editar     |
| DELETE | `/workouts/{id}`   | Apaga treino — apenas o autor pode apagar        |


> **Regra de negócio:** Ao apagar um workout, as associações na tabela `WorkoutExercise` são removidas, mas os exercícios da biblioteca global **não são apagados** dessa forma garantimos consistencia dos nossos dados.

---

## 2.3 Exercises (Exercícios)

Representa a biblioteca global de exercícios disponíveis na plataforma. Os exercícios são partilhados entre todos os utilizadores — a consulta não requer autenticação. Um exercício pode pertencer a vários workouts (**relação N:M**).

| Campo       | Tipo    | Descrição           |
|-------------|---------|---------------------|
| id          | integer | Identificador único |
| title       | string  | Nome do exercício   |
| description | string  | Descrição           |

**Endpoints:**

| Método | Path              | Descrição                           |
|--------|-------------------|-------------------------------------|
| GET    | `/exercises`      | Lista todos os exercícios           |
| GET    | `/exercises/{id}` | Detalhes de um exercício específico |

---

## 2.4 Relações entre Recursos

- **1:N** — Um `User` pode ter vários `Workouts`. Um `Workout` pertence a exatamente um `User`.
- **N:M** — Um `Workout` pode conter vários `Exercises`. Um `Exercise` pode pertencer a vários `Workouts`. A tabela intermédia `WorkoutExercise` guarda os parâmetros específicos de cada associação: número de séries (`sets`) e repetições (`reps`).
